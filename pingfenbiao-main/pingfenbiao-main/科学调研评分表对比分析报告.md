## 四、系统性不足总结

### 4.1 结构设计层面

1. **Synth 维度 100% 缺失 Critical/Mandatory**
   - 所有版本（包括人工样例）均未在 Synth 中设置底线项。科学调研报告的“必须包含摘要”“必须包含时间线/分类表”“必须引用近 2 年文献”等要求应设为 Mandatory 甚至 Critical。

2. **IA 多源引用率不稳定**
   - 在提供多 source 输入的场景下（test1: S1+S2；test2: S1+S2+S3），IA 多源率应稳定 >= 30%。但 test1（22.2%）和 test2 v3（0%）均未达标，说明生成逻辑对“信息获取需交叉验证”的约束不足。

3. **Synth source 链接不可靠**
   - test2 v3 出现 45.5% 的 Synth 项 source_ids 为空。推测原因是：Synth 项多为结构性要求（如 "Does the report maintain a consistent academic tone?"），模型难以将其关联到具体 source，于是留空。但留空会导致评分无据可依。

4. **项数与总分校准不均**
   - test1 项数过少（41），导致总分偏低（88）；test2 v3 项数过多（62），总分虚高（131）。理想情况下，同类型任务的总分应收敛在一个稳定区间（如 100±10）。

### 4.2 内容质量层面

5. **问题表述模板化、领域特化不足**
   - 样例的问题包含大量具体技术实体（Krum, Median, DBA, MNIST, CIFAR-10, Shapley Value, Constraint-and-scale, Homomorphic Encryption 等），可直接用于逐条核对报告内容。
   - Gen-3 问题多为通用模板（"Does the report analyze the mechanism by which..."），虽然语法正确，但**评分时缺乏锚点**，容易流于形式。

6. **SR 动词光谱偏窄**
   - Gen-3 偏好高阶分析动词（analyze, evaluate, compare, argue, synthesize），缺少样例中的 discuss、mention、identify、clarify、address。
   - 后果：评分表对“信息是否被提及/说明”这类基础认知层级的覆盖不足，过于强调高阶推理，可能导致对报告基本信息覆盖度的漏判。

7. **Synth competency 类别膨胀**
   - test2 v3 的 Synth 类别达 5 个（structure, visualization, recommendation, language, integrity），其中 language 和 integrity 主观性强，且 source 全空，建议合并或删除。

## 五、具体改进建议（Prompt / 代码层面）

### 5.1 Prompt 层面

#### 建议 1：强制 Synth 维度设置 Mandatory/Critical 底线项
```
在生成 Report Synthesis 维度时，必须包含至少：
- 1 项 Mandatory：要求报告包含明确的摘要（Abstract）或总结表
- 1 项 Mandatory：要求报告包含分类法/时间线/对比表等可视化结构
- 可选项 Critical：若报告缺失“未来方向”或“近 2 年文献引用”，设 weight=4 的 Critical 项
```

#### 建议 2：IA 多源引用率硬约束
```
在 Information Acquisition 维度，要求：
- 至少 30% 的项必须引用 >=2 个 source_ids
- 若输入文件 >=2，优先对“定义类”“分类类”问题设计多源交叉引用
- 生成后自检：若 IA multi_source_ratio < 0.3，自动替换部分单源项为融合提问
```

#### 建议 3：Synth 项 source 链接兜底策略
```
对于 Report Synthesis 中的结构性要求（如 language、integrity、logical flow）：
- 若无法直接关联到某个 source 的原文依据，则至少关联到 survey/overview source（如 PEFT_Survey.pdf）
- 禁止 source_ids 为空数组；若确实无直接出处，可标记为引用所有输入 source（["S1","S2","S3"]）
- 代码校验：Synth source_linked_ratio 必须 >= 80%，否则触发重生成
```

#### 建议 4：问题表述“实体注入”指令
```
在生成 question 时，要求模型：
1. 从输入 source 中提取 3-5 个具体技术实体/方法名/数据集名
2. 将实体嵌入问题中，避免纯模板句式
3. 示例对比：
   - 差："Does the report analyze the mechanism by which adversaries craft poisoned updates?"
   - 优："Does the report analyze how 'constraint-and-scale' methods allow adversaries to craft poisoned updates that evade L2-norm detection?"
```

#### 建议 5：SR 动词多样化约束
```
在 Scientific Reasoning 维度，要求动词池覆盖以下 4 类：
- 分析类：analyze, evaluate, assess, compare
- 解释类：explain, clarify, demonstrate, derive
- 综合类：synthesize, argue, discuss
- 识别类：identify, mention, differentiate, address
每类至少出现 2 个不同动词，避免单一动词占比超过 30%。
```

### 5.2 代码层面

#### 建议 6：后处理校验脚本（Post-generation Validation）
```python
# 伪代码：task.json 生成后强制校验

def validate_rubric(task_json):
    errors = []
    rubrics = task_json["rubrics"]["dimensions"]
    
    for dim in rubrics:
        items = dim["items"]
        total = len(items)
        c = sum(1 for i in items if i["role"] == "Critical")
        m = sum(1 for i in items if i["role"] == "Mandatory")
        s = sum(1 for i in items if i["role"] == "Standard")
        linked = sum(1 for i in items if i.get("source_ids"))
        multi = sum(1 for i in items if len(i.get("source_ids", [])) >= 2)
        
        # 1. Quality-Driven >= 60%
        if (c + m) / total < 0.60:
            errors.append(f"{dim['dimension_id']}: Quality-Driven < 60%")
        
        # 2. IA multi-source >= 30%
        if dim["dimension_id"] == "information_acquisition" and multi / total < 0.30:
            errors.append("IA: multi-source ratio < 30%")
        
        # 3. Synth source-linked >= 80%
        if dim["dimension_id"] == "report_synthesis" and linked / total < 0.80:
            errors.append("Synth: source-linked ratio < 80%")
        
        # 4. Synth 至少 1 个 Mandatory
        if dim["dimension_id"] == "report_synthesis" and m == 0:
            errors.append("Synth: missing Mandatory items")
    
    return errors
```

```python
# 目标：同类型 literature_review 总分收敛到 100±10
TARGET_SCORE = 100

    scale = TARGET_SCORE / current

        d["max_score"] = round(d["max_score"] * scale)
```

#### 建议 8：Synth 类别去重与精简
```python
# 限制 Synth 中 competency_category 种类为 2-3 个
ALLOWED_SYNTH_CATEGORIES = {"structure", "visualization", "citation"}  # 或 recommendation

def prune_synth_categories(items):
    categories = set(i.get("competency_category", "") for i in items)
    if len(categories) > 3:
        # 将 language / integrity 合并到 structure，或删除
        for i in items:
            if i.get("competency_category") in {"language", "integrity"}:
                i["competency_category"] = "structure"
```

#### 建议 9：Source 链接自动填充兜底
```python
def fill_empty_sources(items, all_source_ids):
    for item in items:
        if not item.get("source_ids"):
            # 策略 1：若 item 属于 synthesis/structure，引用全部 source
            if item.get("competency_category") in {"structure", "synthesis", "citation"}:
                item["source_ids"] = all_source_ids[:]
            else:
                # 策略 2：随机分配一个最相关 source（需配合语义匹配）
                item["source_ids"] = [all_source_ids[0]]
```

## 六、结论与优先级排序

| 优先级 | 改进项 | 影响面 | 实施难度 |
|--------|--------|--------|----------|
| **P0** | Synth 增加 Mandatory/Critical 底线项 | 所有版本 | Prompt 修改，低 |

| **P0** | Synth source 覆盖率兜底（>=80%） | test2 v3 | 代码后处理，低 |

**总体评价**：
