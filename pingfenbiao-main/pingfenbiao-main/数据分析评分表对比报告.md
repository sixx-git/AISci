## 九、系统性不足总结

### 9.1 Gen-2 test1（FL域，最佳版本）的不足

1. **Theoretical Grounding 完全缺失**：SR维度0项，而样例有5项。Gen-2 FL版本过于关注数据层面的convergence/heterogeneity/comparison分析，忽略了理论机制（如公式推导、EMD解释、SGD动力学）的考核。
2. **Synth Mandatory 过少**：仅2项（样例4项），缺少"数据可追溯性"和"引用规范"的强制要求。
3. **SR Mandatory 不足**：14项 vs 样例19项，关键的数据量化要求（如具体数值阈值、accuracy loss幅度）被弱化。
4. **总分偏低**：92分，比样例低10分，主要由SR维度（59 vs 68）和Synth维度（11 vs 14）贡献。

### 9.2 Gen-2 test2（PEFT域）的不足

1. **source覆盖率下降**：84.7%，虽然高于v2，但已低于样例（89.1%）和FL版本（100%）。
2. **SR动词模板化**：多样性比0.556为所有版本最低，高频动词（determine/analyze/identify/explain/compare）各出现3次，句式高度雷同。
3. **Statistical Rigor 薄弱**：仅2项，且均为通用描述，缺乏具体统计检验要求。

### 9.3 Gen-2 test2（PEFT域 v2）的不足

1. **source覆盖率大幅滑坡**：68.3%（比v1下降16.4个百分点），SR维度43%的项无source绑定。这是v2最严重的结构性问题。
2. **Quality-Driven 比例最低**：60.0% C+M占比，78.2% QD分数比例，均为四个版本最低。
3. **Synth Mandatory 缩减至3项**：虽然Synth总项数最多（13项），但Mandatory仅3项，约束力不足。
4. **Factor Analysis 下降**：从12项（v1）降至9项，对影响因素的深度挖掘减弱。

### 9.4 所有 Gen-2 版本的共性不足

1. **Synth 维度无 Critical 项**：与样例一致，但Synth作为报告质量的"守门人"维度，完全缺少Critical项意味着没有"一票否决"级的高 stakes 约束。
2. **Statistical Rigor 普遍薄弱**：所有Gen-2版本均只有2-4项，且提问方式趋于通用（"report confidence intervals"），缺少样例中"具体数值+统计概念"的精确结合。
3. **IA维度引入Critical项的合理性质疑**：样例IA无Critical，Gen-2全部引入1个Critical（主评估指标识别）。对于数据分析报告，IA的核心是"准确提取信息"而非"高 stakes 判断"，Critical放在IA可能导致权重分配失衡。

## 十、具体改进建议

### 10.1 Prompt 层面改进

1. **强制要求 Theoretical Grounding 主题**
   - 在生成SR维度评分标准时，prompt中应明确要求："对于数据分析任务，必须包含至少3-5项与理论机制相关的评分标准，如公式推导、理论假设验证、机制解释等。"
   - 参考样例中的R19-R20（EMD量化、weight divergence与accuracy reduction的理论连接）。

2. **优化 Synth Mandatory 数量**
   - prompt中应设置约束："Synth维度的Mandatory项不得少于4项，必须包含：可视化要求、数据可追溯性、引用规范性、执行摘要/局限性说明。"
   - 参考Gen-2 PEFT的R58/R59（反向完整性检查），保留这类创新项。

3. **控制 SR 动词多样性**
   - prompt中增加："SR维度的评分标准应使用多样化的动词，避免同一动词出现超过3次。优先使用：quantify, trace, derive, cite, validate, deduce, infer, contrast 等。"
   - 避免 Gen-2 PEFT 中 "determine/analyze/identify/explain/compare" 各出现3次的模板化问题。

4. **提升 source 绑定率**
   - prompt中明确："每个评分标准必须关联至少一个source_id，Synth维度的可视化/结构项除外。"
   - 对于PEFT v2的source覆盖率滑坡（68.3%），应设置硬性阈值："source覆盖率不得低于85%。"

5. **增强 Statistical Rigor 的具体性**
   - prompt中应要求："Statistical Rigor项必须包含具体的统计概念（如p-value、置信区间、效应量）与具体数据指标的结合，避免通用描述。"
   - 参考样例R45："MNIST accuracy drops by about 11% under Non-IID"（具体数值+统计观察）。

### 10.2 代码层面改进

1. **后处理校验：source覆盖率检查**
   ```python
   def validate_source_coverage(rubrics, min_ratio=0.85):
       all_items = [item for dim in rubrics['dimensions'] for item in dim['items']]
       linked = sum(1 for item in all_items if item.get('source_ids'))
       ratio = linked / len(all_items)
       if ratio < min_ratio:
           raise ValueError(f"Source coverage {ratio:.1%} below threshold {min_ratio:.1%}")
   ```

2. **后处理校验：Synth Mandatory 数量检查**
   ```python
   def validate_synth_mandatory(rubrics, min_mandatory=4):
       synth_dim = next(d for d in rubrics['dimensions'] if d['dimension_id'] == 'report_synthesis')
       m_count = sum(1 for item in synth_dim['items'] if item['role'] == 'Mandatory')
       if m_count < min_mandatory:
           raise ValueError(f"Synth Mandatory {m_count} below threshold {min_mandatory}")
   ```

3. **后处理校验：动词多样性检查**
   ```python
   def validate_verb_diversity(sr_items, max_verb_freq=3):
       verbs = Counter()
       for item in sr_items:
           match = re.search(r'Does the report ([a-z]+)', item['question'], re.I)
           if match:
               verbs[match.group(1).lower()] += 1
       most_common = verbs.most_common(1)[0][1] if verbs else 0
       if most_common > max_verb_freq:
           raise ValueError(f"Most frequent verb appears {most_common} times, exceeds {max_verb_freq}")
   ```

4. **后处理校验：主题覆盖均衡性**
   ```python
   def validate_topic_coverage(sr_items, required_topics, min_per_topic=1):
       # 检查8大主题是否每项至少出现1次
       for topic in required_topics:
           count = sum(1 for item in sr_items if topic in item.get('rubric_key', ''))
           if count < min_per_topic:
               raise ValueError(f"Topic '{topic}' only appears {count} times")
   ```

5. **引入反向约束（Negative Constraints）的模板**

   - 在代码层面增加一个negative_constraint模板池，在Synth维度中自动插入1-2项反向约束Mandatory项。
